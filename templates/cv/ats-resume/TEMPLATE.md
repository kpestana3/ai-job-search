# Template: ats-resume

- **Type:** CV (industry resume)
- **Engine:** lualatex
- **Page limit:** 1 page
- **Fonts:** Latin Modern (system/TeX-distribution font via `lmodern`, no bundled font files) + FontAwesome5 icon glyphs (`fontawesome5` package, standard TeX Live/MiKTeX package, not a bundled file)
- **Class/packages:** `article` (10pt, letterpaper) + `fontawesome5`, `enumitem`, `etoolbox`, `needspace`, `geometry`, `hyperref`, `xcolor`, `lmodern`, `eso-pic` -- all standard packages, no custom `.cls`. `titlesec` was dropped 2026-08-03 when section headings moved to a hand-built dash-rule design (see below) that no longer needs it. `eso-pic` was added 2026-08-03 for the full-bleed top accent bar (see below).

## Compile command

    cd <output dir> && lualatex -interaction=nonstopmode <file>.tex

## Style rules

- **No moderncv.** This is plain `article` with manual formatting -- chosen specifically to eliminate moderncv banking's wide left-hand date column and generous default spacing, which was leaving visible whitespace and forcing content cuts to hit the page limit. The same real content that used to just barely fill 2 moderncv pages now fits comfortably on 1 page in this template -- see `05-cv-templates.md`'s "Page Budget - Hard 1-Page Limit" for the revised per-section content budget this enables.
- **Top accent bar (added 2026-08-03, revised same day to full bleed):** a 5pt solid `cvblue` rule spanning the *entire physical page width*, edge to edge on the left/right (not capped at the text margins), flush against the physical top edge with zero gap above it. This went through three iterations, each catching a different bug -- see "Known pitfalls" below for all three; don't reintroduce any of them by reworking this by hand:
  1. A `\makebox[\linewidth]{...}` version (text-width only, capped at the left/right margins).
  2. `geometry`'s `top` margin set to `0in` and `\topskip` set to `0pt` in the preamble, to remove the vertical gap above the bar (`\topskip` is a separate mechanism from the margin -- see "Known pitfalls").
  3. Switched to `eso-pic`'s `\AddToShipoutPictureBG` + `\AtPageUpperLeft`, drawn as a page-background layer independent of `geometry`'s margins entirely, so the bar can bleed to the true left/right page edges -- per user feedback that the bar needs to "continue on the side."
  Because the bar is now a background overlay, it does **not** push the rest of the page content down on its own -- a `\vspace*{20pt}` right after `\begin{document}` (starred, not plain -- see "Known pitfalls") manually restores breathing room before the name.
- **Header:** name centered, bold, in the accent color (`cvblue`, `#1F4E79`), **`\huge`** (bumped up from `\Large` 2026-08-03 per user request for a bigger name -- the top-accent-bar clearance above was widened from 15pt to 20pt in the same change to keep the taller name from crowding the bar), no underline (dropped 2026-08-03 to match a cleaner reference aesthetic the user asked to adopt). A real, held credential can be appended directly in `\cvname` (e.g. "[YOUR NAME], Ph.D.") -- never a credential the candidate doesn't actually hold. An optional one-line headline (`\cvheadline`) sits directly under the name -- e.g. a target-title/specialty tagline pulled from the candidate's own real LinkedIn headline or profile, never invented copy; delete the `\cvheadline` line in the HEADER block if you don't want this row. Contact line centered below in plain black text, no icons (phone / email / LinkedIn / location as literal text, pipe-separated) -- see the ATS Parseability note in `05-cv-templates.md` for why icons were removed.
- **Section-heading and list spacing are content-fitting tuning knobs, not fixed values.** The `\vspace{9pt}`/`\vspace{4pt}` in `\rsection` and `itemsep=0pt` in the `\setlist[itemize]` config are this template's defaults (sparse placeholder content has no page-budget pressure), but a real, content-filled resume may need them loosened (more breathing room, less bottom-of-page dead space) or tightened (to fit within 1 page) -- see `cv/main_example_new_format_test.tex`'s tighter `itemsep=0.5pt` / `\rsection` `7pt`/`3pt` values for a real-content example of loosening-then-trimming-back to hit exactly 1 page with no visible dead space. Always re-check page count and bottom-of-page fill after changing these, not just once.
- **Profile Statement:** bold whichever sentence is the strongest/closest fit for the target role (`\textbf{...}` around that sentence only) -- this varies per application and must be re-evaluated for each posting, not copied forward from a previous version.
- **Accent color scope is deliberately narrow:** `cvblue` applies only to the name and section headings/dash rules. Body text, entry titles, and bullets stay black. This mirrors the prior moderncv template's blue-accent convention (`color1`) while keeping the bulk of the page in ATS-safe monochrome.
- **Section headings (redesigned 2026-08-03):** centered, bold, automatically uppercased (`\MakeUppercase` inside `\rsection`, so `\rsection{Work Experience}` in source renders as "WORK EXPERIENCE" -- do not manually type section titles in caps), flanked on both sides by a continuous rule that fills to the margins, replacing the previous left-aligned-label-over-a-full-width-rule design. Built via `\makebox[\linewidth]{...\hrulefill...\hrulefill...}`, not `titlesec` -- see "Known pitfalls" below for two bugs already found and fixed in this exact mechanism (a clipped-dash-pattern version and a `\parfillskip`-skewed-centering version); don't reintroduce either by reworking this by hand. Tight spacing above/below (`\vspace{9pt}` before, `\vspace{4pt}` after, inside `\rsection`).
- **Itemize bullet marker is `\textendash` (`label=\textendash` in the `\setlist[itemize]` config), not the default round bullet dot.** The default bullet glyph has no working ToUnicode mapping under this lualatex+lmodern setup and silently extracts as a bare `�` replacement character in front of every bullet -- a real ATS text-layer defect, caught via the mandatory `pdftotext -layout` check on 2026-08-03. Never revert this to the enumitem default without re-running that check.
- **Entries use `\resumeentry{Title}{Date}{Org}{Location}`**, not moderncv's `\cventry`:
  - Line 1: bold title, `\hfill`, bold right-aligned date -- both on one line, no left-hand date column.
  - Line 2: italic `Organization -- Location` (pass an empty `{}` for Location to omit the dash and location; used for degree entries where a separate line under the title already reads naturally without it).
  - Follow immediately with a normal `itemize` for bullets, or nothing for entries that don't need bullets (e.g. some Education entries).
- **Never place `\vspace{...}` between `\item` entries in an `itemize` list** -- same rule as the moderncv stock template; it produces an intermittently oversized gap before one bullet. A single `\vspace{2pt}` between top-level `\resumeentry` blocks (not inside a list) is fine and expected.
- **Skills/Competencies section:** bold category label + inline comma-separated list per bullet, same convention as the prior moderncv template's Core Competencies section -- carries over unchanged.
- **Letter paper, not A4.** This template defaults to `letterpaper` (US resume convention) rather than the prior template's `a4paper` default, since every current target company is US-based. If a posting is for a non-US office that expects A4, change the `documentclass` option and the `geometry` package will follow.
- **Page limit enforcement:** every `\resumeentry` is preceded by `\needspace{N\baselineskip}` sized for the entry heading plus its first bullet (mirrors the prior template's orphan-prevention convention) -- prevents a title landing at the bottom of a page with its bullets pushed to the next one.
- **Date format, scientific notation, ATS keyword rules:** unchanged from the stock guidance in `05-cv-templates.md` -- this template only changes layout/density, not content rules.
- **No References section.** At 1 page, "Available upon request" is the first thing to cut -- standard for a 1-page resume, and the standalone reference sheet (`08-reference-sheet-templates.md`) already covers this for every application regardless of what the resume itself says.

## Known pitfalls

- `fontawesome5` needs **lualatex**, not pdflatex -- pdflatex commonly fails on modern MiKTeX installs with font-expansion errors on this package (same issue the prior moderncv template had). Always compile with lualatex.
- `\ifstrempty` (from `etoolbox`) is used inside `\resumeentry` to conditionally omit the location dash -- pass literally `{}` as the 4th argument to omit it, not a space or placeholder text.
- The section-heading `\MakeUppercase` wrapper means any inline LaTeX commands inside an `\rsection{...}` argument (e.g. `\textit{}`) will also pass through the uppercase transform and may render oddly -- keep section titles plain text.
- `\needspace{N\baselineskip}` must still precede `\rsection{...}`, not follow it, same as before -- otherwise the heading (and its dash rule) can be orphaned from its own section content across a page break.
- **A section title long enough to approach the full line width will crowd or overflow the heading rule.** `\hrulefill` fills its region with stretch that has no shrinkability -- it can grow to fill extra space but can't compress if the heading text itself is already wide, so an overly long custom section title risks an overfull hbox instead of gracefully losing its flanking rule. Keep section titles short, single-line phrases (the existing five -- Profile Statement, Core Competencies, Work Experience, Education, and any added Publications/Awards/Languages line -- are all safely short).
- **A repeating dash-box pattern for the heading rule (`\leaders\hbox to Npt{...}\hfil`) looks visually clipped/uneven at one end.** A fixed-width repeat can't guarantee it divides evenly into the available stretch, so it often leaves a partial box at one boundary. Fixed 2026-08-03 by switching to a single unbroken `\hrule` (via `\hrulefill`) -- no seams to clip. Don't revert to a dash-box pattern for this heading rule.
- **Building the centered heading as ordinary paragraph text (`\noindent...\par`) skews the left/right rule split unevenly, even with two identical-looking `\hfil`/`\hrulefill` regions.** That line is both the first and last line of its own one-line paragraph, so LaTeX's automatic `\parfillskip` (invisible "0pt plus 1fil" glue always appended at a paragraph's end) becomes a *third* fil-order stretch silently competing with the two rule regions for the same budget -- one side visibly comes out shorter than the other. This was subtle enough to go unnoticed against this template's sparse placeholder text and only became obvious once tested against a fully content-filled resume (`cv/main_example_new_format_test.tex`, 2026-08-03). Fixed by wrapping the whole heading line in `\makebox[\linewidth]{...}`, which sidesteps paragraph-breaking (and `\parfillskip`) entirely -- inside an explicit `\hbox to <dim>`, only the glue actually present in that box competes for stretch. Always test heading centering against real, dense content, not just short placeholder text, since the bug doesn't reliably show up on the latter.
- **Never use `$\bullet$` (or any math-mode bullet symbol) as a plain-text separator in this template** -- it extracts via `pdftotext` as a bare `�` replacement character, the same defect class as the old default itemize bullet marker (see the `label=\textendash` note above). Use `\textbar` (a literal pipe, matching the contact line) or `\textendash` instead. Caught in the `\cvheadline` separator on 2026-08-03 -- always re-run `pdftotext -layout` and check for `�`/`(cid:` after adding any new decorative glyph to this template.
- **Do not add letter-spacing (tracking) to section headings, even via microtype's `\textls` which doesn't touch the underlying text stream.** Tried and reverted 2026-08-03: `pdftotext` infers word boundaries from the *visual gap* between glyphs, not from the text stream itself, and `\textls`'s wider kerning pushed several headings over that threshold -- "Profile Statement" extracted as `P R O F I L E S TAT E M E N T`, "Education" as `E D U C AT I O N`. Worse, it was inconsistent (Core Competencies and Work Experience extracted fine, Profile Statement/Education/Publications & Awards didn't) -- an unpredictable defect, not a uniform trade-off, because it depends on the kerning width between whichever specific letter pairs a given heading happens to contain. If letter-spacing is revisited, `pdftotext -layout` every heading individually, not just a visual read or one sample heading.
- **`\enlargethispage` beyond the page's actual bottom margin silently truncates content -- and a visual PDF preview can fail to catch it.** `\enlargethispage{N\baselineskip}` only tricks the page-breaking algorithm into keeping more content on the current page; it does not resize the physical page. If `N\baselineskip` exceeds the bottom margin's real budget (e.g. `bottom=0.4in` gives ~2.3 baselineskips of true headroom at 10pt), content flows past the paper's physical edge. A rasterized preview (e.g. reading the PDF as an image) can still paint that overflow and look fine, but the actual text layer clips it -- the final line(s) silently vanish from the real, printable/parseable document. **Always verify the fix with `pdftotext -layout` after using `\enlargethispage` for a near-miss, not just a visual read** -- check that the last section's full text is present in the extraction, not just that the page count reads 1. If the needed enlargement exceeds the safe margin budget, tighten/trim real content instead of pushing `\enlargethispage` further.
- **`topsep` in the `itemize` settings must stay `0pt`.** Even `1pt` there silently adds space before the first bullet of every single `\resumeentry`'s list -- and since every list in this template follows an italic org/location line, that extra space reads as "the italic line has weird spacing after it," not as a global list-spacing setting. Measured directly via PDF word coordinates: a `topsep=1pt` produced a ~1pt-larger gap after every org line than the normal line-to-line spacing inside a wrapped bullet. If you ever see this complaint, check `topsep` first, not the font styling on the line above.
- **A placeholder token containing an underscore (e.g. `[YOUR_NAME]`) will not compile.** LaTeX treats a bare `_` outside math mode as a subscript operator and throws "Missing $ inserted." Use a space or hyphen in placeholder tokens instead (`[YOUR NAME]`), never an underscore.
- **`\item [text]` is not the same as `\item text`.** A `[` immediately after `\item` (even with a space before it) is parsed as LaTeX's optional custom-label argument, not literal text -- it silently swallows the bracketed content as the bullet's label instead of its body, and can produce garbled output with punctuation inside the brackets. Never start bullet placeholder text with a literal `[`.
- **A `\rule` placed at `\AtPageUpperLeft` (eso-pic) renders entirely off-page unless lifted downward.** `\rule`'s height extends *upward* from its reference point by default -- at the page's physical top-left corner, "upward" is off the physical page, so `\rule{\paperwidth}{5pt}` alone is invisible. Fixed by using `\rule[-5pt]{\paperwidth}{5pt}` (negative optional lift = lower the box), which shifts the rule down by its own height so it hangs visibly from the top edge instead. If the bar's thickness is ever changed, the lift argument must be updated to match (same magnitude, negative) or the bar goes invisible again.
- **`\textperiodcentered` as a separator inside `\resumeentry`'s 4th argument (e.g. `Springfield, IL \textperiodcentered\ Advisor: ...`) extracts via `pdftotext` as a bare `�` replacement character** -- same defect class as the `$\bullet$` pitfall above. Found 2026-08-07 across `cv/main_example.tex` and previously-submitted application resumes (not retroactively fixed; only the master template was patched). Use `\textbar` instead (matches the header contact-line separator already in use), never `\textperiodcentered` or `$\bullet$`.
- **The Education section's two `\resumeentry` blocks extract with pdftotext in the wrong order: both entries' right-aligned dates get pulled to the very end of the section instead of staying inline with each entry.** Confirmed 2026-08-07 via `pdftotext` (both `-layout` and plain mode) on `cv/main_example.tex` and a per-application resume -- the body text (title, org, bullets) for both Ph.D. and B.A. entries extracts first, then both dates ("July 2023 -- May 2025 January 2017 -- December 2018") get appended together at the end. Work Experience entries, which are otherwise structurally identical (`\resumeentry` + `\hfill`-flushed date), do not show this bug -- the likely trigger is that the B.A. entry has no trailing `itemize` block before the next `\rsection`, unlike every Work Experience entry. Tried and did **not** fix it: adding `\vspace{2pt}`/`\vspace{3pt}` between the two Education entries and before the following section. All the information is still present in the extracted text (nothing is invisible to an ATS keyword search), it's just not in visual/logical order, so a "structured field" parser could mis-map a date to the wrong entry. Real fix not yet found -- if revisited, try giving the B.A. entry (or any bulletless `\resumeentry` immediately followed by a `\rsection`) an actual trailing `itemize`, since that's the one structural difference from the unaffected Work Experience entries.
- **Plain `\vspace{...}` placed at the very top of a page (e.g. right after `\begin{document}`) is silently discarded by TeX's page-breaking algorithm and contributes zero actual space.** This is a standard, easy-to-miss LaTeX quirk -- it's the same underlying reason `\topskip` exists as its own separate mechanism rather than everyone just using `\vspace`. Caught 2026-08-03 when the top-accent-bar clearance space (needed after switching the bar to an `eso-pic` background overlay, which doesn't push content down on its own) was written as plain `\vspace{15pt}` and the name rendered directly underneath the bar, overlapping it -- invisible from reading the source, only visible in the compiled PDF. Use the starred `\vspace*{...}`, which is specifically exempted from this discard rule, for any spacing that must survive at the very top of a page.
